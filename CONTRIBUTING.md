# Contributing to this repo

This guide answers the common questions new contributors have. If anything here is unclear, just ask in an issue — we keep that conversation happening openly.

- **Open an issue first.** Before writing code, describe the change and its motivation in an issue so the team can review scope and avoid stepping on each other's work.
- **Cut a feature branch off `main`.** Use a short, descriptive branch name (e.g. `add-contributing-guide`) and keep the scope of each branch small.
- **Keep pull requests focused.** One change per PR makes review fast and mistakes easy to undo.
- **Write the PR with intent.** Reference the issue number and include a short "what changed" summary in the description — reviewers should not have to dig through the diff to understand it.
- **Push directly to your feature branch.**
